# LANGFENS RQ1-METHOD-BENCH-01 — Experiment portfolio

**Protocol:** EVAL-V3.1. TRAIN contains 1,800 utterances / 12 speakers; DEV_CAL 300 / 2; DEV_SEARCH 599 / 4. DEV_SEARCH is development-exposed: it must not fit model parameters, thresholds, calibrators, weights or hyperparameters. Use genuine WAV plus intended-reference inference. Prefer GPU only with a verified safe lease; CPU neural training is authorized. Record device, budget, runtime and checkpoint identity.

## Selection decision

Initial selected set: H01 similarity-aware realized-phone recognition; H02 normal-only prototype/anomaly scoring; H03 discrete SSL token surprisal; H04 constrained confusion GOP; H05 alignment-free CTC scoring. These are five distinct evidence mechanisms. Start with existing or frozen representations and score screens where feasible. H02's existing prototype run is retained as a completed, limited INSPIRED_IMPLEMENTATION; it is not a SylPh reproduction and should not be rerun without a stated change.

## Shared benchmark procedure

1. Preserve matching event cohorts and raw continuous score semantics. Canonical targets carry C/S/O labels; every utterance produces N+1 insertion-gap scores including leading and trailing gaps.
2. Report AP S, AP O, exact-gap AP I and Macro-3 Error AP only for full three-class models. Also report class P/R/F1, Macro-3 Error F1, binary target MD, exact-gap insertion accuracy and class PR curves. Confidence/FWR are supplementary. Unsupported specialist classes remain N/A, not imputed.
3. Use the EVAL-V3.1 evaluator and retain prediction bundles and receipts. Compare only matched populations, score semantics and inference contracts. External PER/FAR/PCC/F1 are native metrics, not proxies for LANGFENS.
4. First run one small reproducible screen per selected mechanism. Positive findings receive a stronger predeclared experiment and seed replications where resources permit. Retain negative results and commands.
5. Label status separately as RESEARCHED, SELECTED, IMPLEMENTED, TRAINED, BENCHMARKED, SUPPORTED or NOT SUPPORTED. A training receipt requires evidence of execution, not merely a script.
6. Minimum receipt: paper/version/commit, faithful-versus-adapted label, config, seed, inputs/labels, device, budget, runtime, checkpoint hash, coverage validation, evaluator JSON, outputs and limitations.

## Resource policy

Use CUDA only after verifying a safe campaign lease with the shared wrapper. An idle nvidia-smi snapshot or empty lock does not grant a lease; do not conflict with RQ1-UNIFIED-02. While GPU is unavailable, continue literature, feature/cache audits, frozen scoring, lightweight CPU models and statistical analysis. Recheck for a lease at work boundaries. Never describe an adaptation as a full reproduction.
