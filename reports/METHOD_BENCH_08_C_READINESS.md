- Parent steering confirmed a real reporting bug: `summarize()` writes `realized_target_FWR = warning.sum()/n_utts`, i.e., total S/O warning count/utterance, not false warnings/utterance. The separate `binary_false_warnings` column counts only gold-correct target alerts. The downstream `summarize_target_warning_budgets.py` repeats the total-warning numerator. Thus named FWR values in the legacy CSV are mislabeled/invalid FWR estimates. Their raw outer selected policies can be described using EVAL target FWR=`false_warnings/n_outer_utterances` (equal to `(FP_S+FP_O)/n_outer_utterances` here); do **not** substitute narrower gold-C-only `binary_false_warnings`, and this arithmetic correction does not retroactively make policies selected at a false-warning budget. EVAL-V3.1 joint FWR counts every incorrectly typed/false prediction: target FP includes both S and O class false positives (a gold substitution warned as omission is an FP-O); add exact-gap false insertion alarms (predicted I at a gold-negative gap), then divide by the shared utterance count. It is **not** gold-C-only `binary_false_warnings`. Target-only seed101 nominal `.2` across folds: total target alerts/utt `.105`; correct target FWR=`false_warnings/n_utt`=`57/1800=.03167` (equivalently `(FP_S+FP_O)/1800`), whereas gold-C-only binary false alarms are `52/1800=.02889`. Fixed neural+E4 `.2`: `.22278` total alerts/utt, correct target FWR=`122/1800=.06778` (FP_S+FP_O), versus gold-C-only `.05833`. Seed202 neural-only `.2`: `.16` total/utt, correct target FWR=`85/1800=.04722`, gold-C-only `.04222`; fixed neural+E4 `.2`: `.23056` total/utt, correct target FWR=`133/1800=.07389`, gold-C-only `.06444`. The nominal budgets select total warning ranks in current code; no exact matched-FWR conclusion is warranted. The `false_warnings` column agrees with FP_S+FP_O in target-only data; `binary_false_warnings` is narrower and must not be used as EVAL FWR. Per-class P/R/F1 in CSV are raw classifications, but their threshold policies are warning-count policies, not frozen false-warning-budget policies.
- `fit_cross_meta()` in `evaluate_nested_target_warning_budgets.py` cross-fits only the **meta classifier** across three inner groups. For meta-held group j, its base scores were generated by ordinary inner OOF base models trained on other outer-pool groups, and those fits include speakers in j. Therefore it is outer-fold valid (the entire outer test group is absent), but the meta-held labels are not isolated from the base pipeline used to create the other meta-training rows. It is not strictly inner-generalization-valid for estimating calibration/threshold performance. Thresholds are still chosen only with outer-training labels and then applied to outer test, so this is not direct outer-label leakage; it can bias inner policy estimates/selection. Report learned meta AP on outer-held events as valid, but do not characterize inner threshold selection as fully nested; use strict meta crossfit or fixed fusion in future.
- MB07-B receipt reports CUDA execution (`device=cuda`, ~80.86 sec; GTX1650 4-GB environment). The artifact records CUDA use, but the MB07 run lacks a verifiable valid GPU lease receipt in inspected provenance; classify as a historical lease/provenance deviation. Do not retroactively describe MB07 as violating the later MB08 CPU-only freeze. This does not change held-out AP arithmetic, but weakens runtime/lease reproduction; no MB08 GPU use occurred. MB07-A direct/Fusion receipts report CPU; seed101/202 direct runs and neural/E4 outer score artifacts have event-level provenance, but direct receipts do not preserve reusable final model checkpoints.
